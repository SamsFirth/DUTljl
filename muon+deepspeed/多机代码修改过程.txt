与z2同样的问题，allreduce张量形状不一致，速度也更慢

帖子：
https://github.com/Lightning-AI/pytorch-lightning/discussions/13997
意思是：
某些 expert / MoE 参数在某些 rank 的这个 step 上没有参与 backward（grad=None），但在另一些 rank 上参与了（grad tensor 存在），ZeRO2 在构建 reduce bucket 时会把“参与反向的参数集合”拼成 bucket，导致 bucket 长度在不同 rank 上不同

观察模型文件夹中modeling_deepseek.py的moe类的moe函数代码：
def moe(self, hidden_states: torch.Tensor, topk_indices: torch.Tensor, topk_weights: torch.Tensor):
        r"""
        CALL FOR CONTRIBUTION! I don't have time to optimise this right now, but expert weights need to be fused
        to not have to do a loop here (deepseek has 256 experts soooo yeah).
        """
        final_hidden_states = torch.zeros_like(hidden_states, dtype=topk_weights.dtype)
        expert_mask = torch.nn.functional.one_hot(topk_indices, num_classes=len(self.experts))
        expert_mask = expert_mask.permute(2, 0, 1)

        for expert_idx in range(len(self.experts)):
            expert = self.experts[expert_idx]
            mask = expert_mask[expert_idx]
            token_indices, weight_indices = torch.where(mask)

            if token_indices.numel() > 0:
                expert_weights = topk_weights[token_indices, weight_indices]
                expert_input = hidden_states[token_indices]
                expert_output = expert(expert_input)
                weighted_output = expert_output * expert_weights.unsqueeze(-1)
                final_hidden_states.index_add_(0, token_indices, weighted_output)

        # in original deepseek, the output of the experts are gathered once we leave this module
        # thus the moe module is itelsf an IsolatedParallel module
        # and all expert are "local" meaning we shard but we don't gather
        return final_hidden_states.type(hidden_states.dtype)
当某个 expert 在某个 rank 上没有任何 token 被路由到时，这个 expert 的 expert(...) 根本不执行，于是它的所有参数都不会出现在 autograd 图里，backward 以后这些参数的 .grad 就是 None（不是 0）。在另一些 rank 上该 expert 可能有 token，于是 .grad 是 tensor。

修改一下代码：
    def moe(self, hidden_states: torch.Tensor, topk_indices: torch.Tensor, topk_weights: torch.Tensor):
        r"""
        CALL FOR CONTRIBUTION! I don't have time to optimise this right now, but expert weights need to be fused
        to not have to do a loop here (deepseek has 256 experts soooo yeah).
        """
        import os
        import torch.distributed as dist

        if (not dist.is_available()) or (not dist.is_initialized()) or dist.get_rank() == 0:
            print("[DeepseekV3MoE] using patched moe() from modeling_deepseek.py", flush=True)

        final_hidden_states = torch.zeros_like(hidden_states, dtype=topk_weights.dtype)
        expert_mask = torch.nn.functional.one_hot(topk_indices, num_classes=len(self.experts))
        expert_mask = expert_mask.permute(2, 0, 1)

        for expert_idx in range(len(self.experts)):
            expert = self.experts[expert_idx]
            mask = expert_mask[expert_idx]
            token_indices, weight_indices = torch.where(mask)

            if token_indices.numel() > 0:
                expert_weights = topk_weights[token_indices, weight_indices]
                expert_input = hidden_states[token_indices]
                expert_output = expert(expert_input)
                weighted_output = expert_output * expert_weights.unsqueeze(-1)
                final_hidden_states.index_add_(0, token_indices, weighted_output)
                
        zero = final_hidden_states.sum() * 0.0
        for expert in self.experts:
            for p in expert.parameters():
                if p.requires_grad:
                    zero = zero + p.reshape(-1)[0] * 0.0

        final_hidden_states = final_hidden_states + zero

        # in original deepseek, the output of the experts are gathered once we leave this module
        # thus the moe module is itelsf an IsolatedParallel module
        # and all expert are "local" meaning we shard but we don't gather
        return final_hidden_states.type(hidden_states.dtype)
让每个expert即使没有token，也会让其grad tensor为0，而不是none，保持不同rank的deepspeed的bucket形状一样。
